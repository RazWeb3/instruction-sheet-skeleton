# Structure Steering — Instruction-Sheet Skeleton

## Repository layout (fixed)

```
<repo>/
  .kiro/            ← steering / specs / hooks. Repo root, never gitignored.
  LICENSE           ← MIT, at root so GitHub detects it
  README.md         ← English
  core/             ← shared skeleton (§3.2 of the execution sheet)
    codec.js        ← ?data= encode/decode (gzip + base64url), DOM-free
    validate.js     ← type/schemaVersion + per-app schema checks, DOM-free
    store.js        ← IndexedDB thin Promise wrapper, one store per app
    ui.js           ← shared UI parts (import notice, empty state, list → detail)
  apps/
    player/         ← App 1: Pack Player (listening-pack)
    board/          ← App 2: Memory Board (memory-board)
  instructions/     ← user-facing AI instruction sheets (player.md, board.md)
  samples/          ← demo sample data + its import links
```

## Rules

- One public GitHub repo. App URLs stay live and free to test until the
  judging period ends (**2027-01-29**).
- Each app is a single screen, read-focused. App-specific display and
  playback live in that app's folder, never in `core/`.
- `core/` holds exactly the four functions: codec, validation, storage,
  common UI. Nothing else goes in.
- Instruction sheets live in `instructions/` and are loadable by raw URL so
  an AI chat can read them directly.
- Samples are generated by following the instruction sheets, not hand-made
  shortcuts — the sample proves the sheet works.
- Secrets (Kiro user ID, credit code, etc.) never go in the repo, chat, or
  memory. The Kiro user ID lives only in Raz's Kiro settings screen.
