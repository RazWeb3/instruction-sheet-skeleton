# Design — Pack Player (App 1)

## Overview

One screen under `apps/player/`, built only on `core/` (codec, validation,
storage, common UI). No build step, no framework, no audio files.

## Data format

```json
{
  "type": "listening-pack",
  "schemaVersion": 1,
  "title": "Fruits",
  "lang": "en-US",
  "sections": [
    {
      "heading": "Common fruits",
      "items": [
        { "text": "apple", "meaning": "りんご", "note": "an apple a day" }
      ]
    }
  ]
}
```

- `title` (required), `lang` (optional, default `"en-US"`).
- `sections`: array of `{ heading, items }`; `items`: array of
  `{ text (required), meaning?, note? }`.
- Validation is `core/validate.js`; the player adds no extra rules.

## Layout (single screen)

- Header: app title + speed selector (0.75 / 1.0 / 1.25).
- List view: imported packs (title + item count). Empty state from `core/ui.js`
  when there are none, with the sample-import button.
- Detail view: section headings, items as rows (text + meaning). Tap an item
  to speak it; a play-all control speaks the whole pack in order and
  highlights the current item; a stop control ends playback.
- Footer: "Export learning memo" button producing plain text.

## Playback

- `speechSynthesis` only. One `SpeechSynthesisUtterance` per item, `lang`
  from the pack. Continuous mode chains utterances with `onend`.
- Stop cancels the queue (`speechSynthesis.cancel()`). Switching packs
  cancels playback first.
- No audio files, no cloud voices, no pre-recorded audio.

## Export memo

Plain text, e.g.:

```
Pack: Fruits
Section: Common fruits
- apple — りんご
```

Generated from the open pack only. No extra commentary added.

## Sample

`samples/player-sample.json` — one short English-word pack (a few items,
one section), generated by following `instructions/player.md`, with its
import link in `samples/` and on the empty state.

## Sokqa document-pack compatibility (added 2026-11-12)

The player also accepts Sokqa's own pack format so a pack made for the
Sokqa app can be checked on the web first. Schema (from the Sokqa app's
validator):

- Top level: `type: "document"`, `schemaVersion: 1`, `title` (required),
  `language` (required), `packMode` / `globalTags` / `assetBaseUrl` /
  `replaces` (optional, ignored here)
- `documents` (required, non-empty): `{ id (required), text (required),
  tts?: { text?, textLanguage?, audioUrl?, audioPath? }, tags? }`

Normalization on import (the stored form stays the player's own model):

| Sokqa document pack | Player model |
|---|---|
| pack `title` | pack title |
| pack `language` | pack `lang` |
| each document | one section, heading `Section N` (1-based) |
| document `text` | the section's single item, display text |
| document `tts.text` (if present) | the item's speak text (playback uses it instead of the display text) |
| document `tts.textLanguage` (if present) | the item's speak lang (overrides pack lang for that item) |
| `tts.audioUrl` / `tts.audioPath` | ignored — web playback is TTS-only by design |

Validation for `type: "document"` lives in `core/validate.js` alongside
the other per-type schemas. The player accepts `listening-pack` and
`document`; the board still accepts only `memory-board`.
