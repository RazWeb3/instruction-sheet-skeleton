# Instruction-Sheet Skeleton

A lean, local-only skeleton for **AI instruction-sheet apps** — built with Kiro for [Kiroween 2026](https://kiroween.devpost.com/) (Skeleton Crew category).

## The pattern

1. A public **instruction sheet** (Markdown) tells the user's own AI chat how to generate data as JSON.
2. The AI returns an **import link**: the JSON, gzip-compressed and base64url-encoded, in a `?data=` query parameter.
3. The app decodes and validates the link, stores the data **locally in the browser** (IndexedDB), and works fully offline afterwards.

No API keys. No server. No AI/LLM API inside the app — generation always happens outside the app, in the user's own AI chat.

## How it works
1. Give the raw URL of an instruction sheet to your own AI chat, and describe what you want to learn or remember.
2. The AI follows the sheet, produces JSON in the required schema, and encodes it as an import link.
3. Open the link. The app decodes it (base64url, then gunzip), validates it against the schema, and shows a clear error if anything is wrong.
4. Valid data is saved in the browser's IndexedDB under its title. Re-importing the same title replaces the entry.
5. After that the app works offline. Nothing leaves the browser.
## Import rule

Re-importing data with the same title **replaces** the existing entry — there is at most one entry per title in each app.

## What's in this repo

- `index.html` and `theme.css` — the landing page and the shared skeleton theme (plain CSS, no frameworks).
- `core/` — the skeleton: import-link codec, schema validation, local storage, shared UI parts. Nothing else.
- `apps/player/` — **Pack Player**: imports a listening pack and plays it back with the browser's built-in text-to-speech.
- `apps/board/` — **Memory Board**: imports a memory board and displays it as cards with tag filtering.
- `instructions/` — the two public instruction sheets (AI-agnostic; any chat AI can follow them).
- `samples/` — sample data and import links, generated by following the instruction sheets.
- `.kiro/` — the steering documents and specs this project is built from, spec-first.

## How Kiro was used
- **Steering** (`.kiro/steering/`): `product.md`, `tech.md` and `structure.md` fix the product definition, the no-build static-site approach, and the repository layout, so every session starts from the same constraints.
- **Specs** (`.kiro/specs/`): `core`, `player` and `board` each have requirements, design and tasks. Specs were written first and implemented in that order.
- **Hook** (`.kiro/hooks/run-tests-on-save.json`): runs `node --test` whenever a file in `core/` is saved, so the skeleton is re-tested on every change.
- **Property-based tests** (`core/codec.test.js`): the codec is checked with generated inputs. Any JSON value must round-trip unchanged, and truncated links, non-base64url strings and non-gzip bytes must always be rejected.
